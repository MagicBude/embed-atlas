# UART 帧格式、波特率与实际传输位数

## 本文解决什么问题

发送 100 byte 的 8N1 数据为什么在线路上要传 1000 bit？`printf` 已返回为什么 TX 引脚仍在变化？两端都配置 `115200` 为什么还会乱码？本文从一帧的真实结构建立传输时间与排错模型。

## 阅读前需要知道什么

- UART 是异步串行通信，发送端和接收端没有共享每个 bit 的时钟线。
- 文本必须先编码为 byte；中文 UTF-8 通常不止一个 byte，可回顾[字节、字符、编码与字符串](../foundations/bytes-characters-encoding)。

## 空闲、起始位与停止位

常见 UART 线路空闲为高电平。一帧开始时发送端拉低一个起始位，接收端据此对齐采样时刻；随后发送数据位、可选校验位和停止位。

```text
空闲  起始     8 个数据位（通常 LSB first）       停止  空闲
 1      0    D0 D1 D2 D3 D4 D5 D6 D7              1     1
```

“8N1”表示：

- `8`：8 个数据位。
- `N`：无奇偶校验（None）。
- `1`：1 个停止位。

它还固定包含 1 个起始位，所以每帧不是 8 bit，而是 `1 + 8 + 0 + 1 = 10 bit`。

## 线路位数和理论时间

设：

- 数据位数为 `D`。
- 启用校验时 `P=1`，否则 `P=0`。
- 停止位数为 `S`。
- 要发送的 byte/字符帧数量为 `N`。
- 波特率为 `B`，在常见二进制 UART 中每个码元承载 1 bit，因此数值上常写作 `bit/s`。

则：

```text
每帧位数 = 1 + D + P + S
总线路位数 = N × 每帧位数
理论时间（s） = 总线路位数 ÷ B
```

100 byte、115200、8N1：

```text
总线路位数 = 100 × 10 = 1000 bit
理论时间 = 1000 / 115200 s ≈ 8.681 ms
```

这是连续发送且无额外间隔的下限。软件调度、FIFO 断流、流控和协议帧间隔都会增加实际时间。

## 波特率从外设时钟怎样产生

MCU UART 通常用外设时钟经过整数或小数分频产生采样时钟。实际波特率不能总是精确等于目标值：

```text
误差（%） = (实际波特率 - 目标波特率) / 目标波特率 × 100%
```

两端误差的相对方向很重要：一端偏快、另一端偏慢时，总采样漂移更大。可接受上限取决于过采样率、帧长度、接收器实现和时钟精度，不能把某个固定百分比当成所有芯片的规范。

工程上应按芯片参考手册的分频公式枚举可用配置，并用逻辑分析仪测量 bit 宽度。晶振、内部 RC 温漂和低功耗时钟切换都可能改变实际误差。

## 奇偶校验与错误标志

偶校验让数据位加校验位中的 `1` 总数为偶数；奇校验则为奇数。它只能检测一部分 bit 错误，不提供帧同步、重传或消息级完整性。

UART 接收器常见状态包括：

- Parity Error：校验位不符合配置。
- Framing Error：期望停止位时线路不是有效停止状态。
- Overrun Error：新数据到达前软件未取走旧数据。
- Break：线路保持低电平超过正常帧长度，用于特殊信号。

错误状态的清除顺序具有芯片差异，必须按参考手册读状态寄存器和数据寄存器。

## “寄存器空”不等于“线路发送完成”

发送路径通常至少有：

```text
软件 / DMA → 发送数据寄存器或 FIFO → 移位寄存器 → TX 引脚
```

发送数据寄存器空（常见名称 TXE、THRE）只说明可以写入下一个 byte；最后一个停止位可能仍在移位寄存器中。关闭 RS-485 方向使能、切换引脚或进入休眠前，应等待“发送完成”（常见名称 TC、TEMT），并核对具体外设语义。

## UART 只负责 byte 帧，不负责消息边界

UART 硬件知道起始位和停止位，却不知道应用协议中的“这一包结束了”。上层通常用以下方式划分帧：

- 固定长度。
- 长度字段。
- 特殊分隔符，并处理转义。
- 空闲时间间隔。
- 校验和/CRC 配合帧头与长度。

使用 DMA 循环接收时，空闲线中断只是划分候选片段的手段；片段仍可能因调度、FIFO 或线路间隔与协议帧边界不完全一致。

## 常见错误与排查

| 现象 | 常见原因 | 检查方法 |
| --- | --- | --- |
| 所有字符乱码 | 波特率、数据位、校验或停止位不一致 | 同时核对双方配置并测量 TX bit 宽度 |
| 偶发错字且随温度变化 | 时钟误差或信号完整性边界 | 测实际波特率、检查时钟源和电平 |
| 连续发送时丢 byte | RX overrun、DMA/FIFO 处理不及时 | 读取错误标志与缓冲区水位 |
| 最后一个 byte 被截断 | 只等 TXE 后就关外设/方向 | 等待 TC/TEMT 再切换 |
| 英文正常、中文异常 | 两端编码不同或按字符数分配 byte | 抓取原始 HEX 并按 UTF-8 byte 长度检查 |

## 示例：UTF-8 文本的传输时间

文本 `A中` 编码为 UTF-8 是 `41 E4 B8 AD`，共 4 byte。115200、8N1 连续发送的理论时间：

```text
4 × 10 / 115200 s ≈ 0.347 ms
```

不能按“两个字符”计算为 20 bit。
