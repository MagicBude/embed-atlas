# 二进制补码与有符号整数范围

调试器里的 `0xD6` 为什么可能是 `-42`？把 8 位负数放进 16 位寄存器时，为什么高位要补 `1`？为什么 8 位有符号整数能表示 `-128`，却不能表示 `+128`？这些现象都来自同一个模型：在固定 N 位中，用二进制补码（Two's Complement）解释位模式。

## 本文解决什么问题

读完本文，你应该能够：

- 从位宽推导补码有符号整数的范围。
- 在负数、无符号位模式、二进制和十六进制之间互相转换。
- 解释“逐位取反再加一”为什么有效，以及它依赖什么前提。
- 区分符号扩展、零扩展和截断，并判断它们是否保持原数值。
- 解释算术右移与逻辑右移对负数产生不同结果的原因。
- 识别最小负数取反、同位宽加法溢出等常见边界。

## 阅读前需要知道什么

- 建议先读 [整数、进制与位模式](./integer-radix-bit-pattern)。
- 知道 N 位无符号整数范围是 `0`～`2ᴺ - 1`。
- 会把一个十六进制数字对应到 4 个二进制位。

本文讨论的是固定宽度位模式的数学解释。具体编程语言中的整数提升、类型转换和溢出规则，会在“平台与语言差异”中单独区分。

## 补码不是在最高位前面放一个负号

先观察 4 位系统的全部 16 种位模式：

| 位模式 | 无符号值 U | 4 位补码值 S | 位模式 | 无符号值 U | 4 位补码值 S |
| --- | ---: | ---: | --- | ---: | ---: |
| `0000` | 0 | 0 | `1000` | 8 | -8 |
| `0001` | 1 | 1 | `1001` | 9 | -7 |
| `0010` | 2 | 2 | `1010` | 10 | -6 |
| `0011` | 3 | 3 | `1011` | 11 | -5 |
| `0100` | 4 | 4 | `1100` | 12 | -4 |
| `0101` | 5 | 5 | `1101` | 13 | -3 |
| `0110` | 6 | 6 | `1110` | 14 | -2 |
| `0111` | 7 | 7 | `1111` | 15 | -1 |

补码没有改变任何一位，只是把无符号范围的上半段映射到负数：

```text
如果 U < 2ᴺ⁻¹：S = U
否则：          S = U - 2ᴺ
```

对 4 位 `1010`：

```text
U = 10
S = 10 - 16 = -6
```

因此，把最高位称为“符号位”可以帮助快速判断正负，但不能把它理解成独立于其他位的正负号。最高位仍然参与数值计算。

## 最高位为什么具有负权重

N 位补码也可以直接按位权计算：

```text
S = -bₙ₋₁ × 2ᴺ⁻¹ + bₙ₋₂ × 2ᴺ⁻² + ... + b₁ × 2¹ + b₀ × 2⁰
```

其中每个 `bᵢ` 只能是 `0` 或 `1`。与无符号位权相比，只有最高位的权重从正的 `2ᴺ⁻¹` 变成了负的 `-2ᴺ⁻¹`。

以 8 位 `1101 0110` 为例：

```text
S = -128 + 64 + 16 + 4 + 2
  = -42
```

这和先按无符号得到 `214`，再计算 `214 - 256` 完全一致。两种方法可以互相核对。

## 为什么范围在负方向多一个数

当最高位为 `0` 时，其余 N - 1 位可以表示：

```text
0 ～ 2ᴺ⁻¹ - 1
```

当最高位为 `1` 时，最小值出现在其余位全为 `0`：

```text
-2ᴺ⁻¹
```

最大负数出现在所有位全为 `1`，其值是 `-1`。所以 N 位补码范围是：

```text
-2ᴺ⁻¹ ～ 2ᴺ⁻¹ - 1
```

| 位宽 | 最小值 | 最大值 |
| ---: | ---: | ---: |
| 8 bit | -128 | 127 |
| 16 bit | -32768 | 32767 |
| 32 bit | -2147483648 | 2147483647 |
| 64 bit | -9223372036854775808 | 9223372036854775807 |

零只需要 `000...000` 一种表示，因此不会出现“正零”和“负零”各占一个位模式。省下的那个模式落在负数一侧，形成不对称范围。

## 怎样得到一个负数的补码位模式

### 方法一：加上 2ᴺ

若负数 `x` 在 N 位补码范围内，对应的无符号位模式为：

```text
U = 2ᴺ + x
```

把 `-42` 写成 8 位补码：

```text
U = 256 + (-42)
  = 214
  = 0xD6
  = 0b11010110
```

这种方法直接体现补码是在模 `2ᴺ` 的环中选择一个代表位模式。

### 方法二：取反再加一

也可以先写出正数绝对值的 N 位模式，再逐位取反并加一：

```text
  42        0010 1010
逐位取反    1101 0101
加一        1101 0110
结果        0xD6
```

它成立的原因不是口诀，而是 N 位逐位取反满足：

```text
NOT U = (2ᴺ - 1) - U
```

再加一得到：

```text
NOT U + 1 = 2ᴺ - U
```

这正是 `-U` 在模 `2ᴺ` 下的位模式。

::: warning 必须先固定宽度
对 `0010 1010` 取反得到 `1101 0101`，是因为这里明确限定为 8 位。若按 16 位取反，结果会是 `1111 1111 1101 0101`。离开位宽谈“取反”没有唯一答案。
:::

## 最小负数为什么是特殊边界

8 位最小负数 `-128` 的位模式是：

```text
1000 0000
```

它的数学相反数是 `+128`，但 8 位补码最大只能表示 `+127`。若仍然只保留 8 位，对它取反再加一会得到：

```text
  1000 0000
取反 0111 1111
加一 1000 0000
```

结果又回到相同位模式。这里不是 `-128 = +128`，而是数学结果已经超出 8 位有符号范围，截断后只能回绕到原模式。

因此，下面这种写法需要先处理最小值边界：

```c
/* 教学示意：具体行为仍取决于类型和所用 C 标准。 */
if (value == INT_MIN) {
    /* 不能假设 -value 可以由同一个 signed int 表示。 */
}
```

## 符号扩展怎样保持负数不变

把较窄的补码值放入更宽的位模式时：

- 非负数在高位补 `0`。
- 负数在高位补 `1`。

这个过程叫符号扩展（Sign Extension）。例如把 8 位 `-42` 扩展为 16 位：

```text
8 位     1101 0110              = 0xD6   = -42
16 位    1111 1111 1101 0110    = 0xFFD6 = -42
```

为什么补 `1` 后数值不变？设原来的 N 位无符号模式为 `U`，扩展到 M 位时，新增加的高位全为 `1`。新模式的无符号值为：

```text
U' = U + (2ᴹ - 2ᴺ)
```

按 M 位补码解释：

```text
S' = U' - 2ᴹ
   = U + (2ᴹ - 2ᴺ) - 2ᴹ
   = U - 2ᴺ
```

这正是原来的 N 位补码值。

### 符号扩展和零扩展不能混用

如果把 8 位 `0xD6` 高位补 `0`：

```text
0000 0000 1101 0110 = 0x00D6 = 214
```

位模式作为无符号值从 `214` 扩展到 `214`，但作为有符号值不再是 `-42`。所以：

- 保持补码有符号值，使用符号扩展。
- 保持无符号值，使用零扩展（Zero Extension）。

## 缩窄与截断可能改变数值

扩展可以保值，反方向的缩窄却不一定。把 16 位 `300` 截断为 8 位：

```text
300 = 0x012C
保留低 8 位 → 0x2C = 44
```

截断在位模式层面相当于模 `2ᴺ`，但只有当原值落在目标类型可表示范围内时，目标补码值才和原值相同。

工程中看到强制类型转换、寄存器赋值或协议字段打包时，应同时检查：

1. 目标位宽是多少。
2. 保留低位是否是协议明确要求。
3. 原值超出范围时应该报错、饱和还是截断。

## 算术右移与逻辑右移

右移需要回答“高位补什么”：

- 逻辑右移（Logical Right Shift）高位补 `0`，适合把输入当作无符号位模式。
- 算术右移（Arithmetic Right Shift）高位补符号位，常用于保持补码负数的符号。

8 位 `0xD6` 按补码解释为 `-42`，右移 2 位：

```text
原始          1101 0110
逻辑右移 2    0011 0101 = 0x35 = 53
算术右移 2    1111 0101 = 0xF5 = -11
```

算术右移结果是 `-11`，对应向负无穷方向取整的 `-42 / 4`。不要仅凭运算符长相推断具体语言一定采用这种规则；工具、CPU 指令和编程语言需要分别核对。

## 溢出时位模式和语言结果不是一回事

假设使用 8 位位模式计算 `100 + 60`：

```text
  0x64
+ 0x3C
= 0xA0
```

低 8 位是 `0xA0`。它按无符号解释为 `160`，按 8 位补码解释为 `-96`。数学和 `160` 已经超出 8 位补码范围，所以发生了有符号范围溢出。

在纯固定位宽电路模型中，可以描述“保留低 8 位”；在源代码中，却不能因此断言所有语言和所有类型都会静默回绕。语言可能规定回绕、抛出、调试模式检查，或把某些有符号溢出视为未定义行为。

::: tip 一个常用的加法溢出观察法
对同位宽补码加法，如果两个操作数符号相同，而结果符号不同，则数学结果超出了该有符号范围。硬件通常也会提供相应状态信息，但具体标志和读取方式由处理器架构决定。
:::

## 常见错误与排查

| 现象或说法 | 问题在哪里 | 正确检查方法 |
| --- | --- | --- |
| “最高位是 1，所以剩余位就是绝对值” | 把补码误当成符号-数值表示 | 使用 `U - 2ᴺ` 或负权位权计算 |
| “负数就是取反” | 少了加一，而且没有说明位宽 | 固定 N 位后取反再加一，或直接计算 `2ᴺ + x` |
| “8 位有符号范围是 -127～127” | 忘记补码只有一个零 | 从 `-2ᴺ⁻¹`～`2ᴺ⁻¹ - 1` 推导 |
| “扩大类型时高位总是补 0” | 负数零扩展会改变有符号值 | 先确认要保持 signed 还是 unsigned 解释 |
| “右移负数就是除以 2” | 缺少逻辑/算术右移和舍入方向 | 检查高位填充值及语言或指令规范 |
| “位模式回绕等于 C 有符号溢出规则” | 混淆硬件位结果与源语言语义 | 先确认类型、整数提升和所用语言标准 |
| “`abs(INT_MIN)` 一定得到正数” | 同位宽中不存在对应的最大正值 | 显式检查最小值，或先转换到能表示结果的更宽类型 |

## 平台与语言差异

### CPU 与指令集

处理器可能提供不同宽度的运算和显式扩展指令。例如 RISC-V RV64 的部分 `W` 后缀指令只计算低 32 位，再把 32 位结果符号扩展到寄存器宽度。阅读反汇编时，要把“计算宽度”和“目标寄存器宽度”分开看。

### JavaScript / TypeScript

ECMAScript `BigInt` 不限制固定位宽，负数位运算按左侧有无限个 `1` 的补码模型定义。EmbedAtlas 使用 `BigInt.asUintN` 和 `BigInt.asIntN` 把任意整数明确约束到 N 位，再显示无符号和有符号结果。

### Java

Java 明确规定整数采用补码表示，并分别提供 `>>` 算术右移和 `>>>` 逻辑右移。Java 对最小 `int` 或 `long` 取负会回到同一个最小值，不抛出异常。这个行为可以帮助理解边界，但不能直接套用到 C/C++。

### C 和 C++

C23 已统一采用补码整数表示，但“对象怎样表示”和“表达式溢出、提升、转换、右移怎样执行”仍然是不同问题。旧版本标准、C++ 版本、编译器选项和具体类型也需要分别核对。首批计划中的《C 定宽整数、提升与溢出边界》会专门解释这些差异，文章发布前不创建无效入口。

## 自测

### 题目

1. 8 位 `0xE9` 按补码解释是多少？
2. 把十进制 `-18` 写成 8 位十六进制补码。
3. 8 位 `0x80` 符号扩展到 16 位后是什么？
4. 8 位 `0x80` 零扩展到 16 位后，按有符号整数解释是多少？
5. 为什么 16 位有符号整数不能表示 `32768`？
6. 8 位 `0xE8` 算术右移 3 位和逻辑右移 3 位分别是什么？

### 答案

1. 无符号值 `U = 233`，所以 `S = 233 - 256 = -23`。
2. `256 - 18 = 238 = 0xEE`。
3. `0xFF80`，仍表示 `-128`。
4. `0x0080`，按 16 位有符号整数解释为 `128`。
5. 16 位补码最大值是 `2¹⁵ - 1 = 32767`；`0x8000` 被分配给最小值 `-32768`。
6. `0xE8` 是 `1110 1000`，算术右移得到 `1111 1101 = 0xFD = -3`；逻辑右移得到 `0001 1101 = 0x1D = 29`。
