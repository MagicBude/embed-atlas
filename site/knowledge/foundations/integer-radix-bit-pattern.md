# 整数、进制与位模式

嵌入式开发中经常同时看到 `42`、`0x2A`、`0b00101010` 和寄存器里的 8 个高低电平。它们可以表达同一个数值，但并不是同一种东西。理解它们的层次，是读寄存器、协议报文、内存数据和位运算代码的共同基础。

## 本文解决什么问题

读完本文，你应该能够：

- 区分数学数值、进制写法和固定宽度位模式。
- 使用位权把二进制、十进制和十六进制互相核对。
- 解释为什么 `0xFF` 在 8 位下既可能读作 `255`，也可能读作 `-1`。
- 判断一次转换还缺少位宽、有符号性或字节序中的哪些信息。
- 看懂左移截断、前导零和“只保留低 N 位”的含义。

## 阅读前需要知道什么

- 会进行整数加法和乘法。
- 知道 bit 表示一个二进制位，取值为 `0` 或 `1`。

不要求已经学过补码、C 语言整数提升或计算机组成。

## 先分清三个层次

### 数值：抽象的整数

数学整数四十二是一个抽象数值。无论写成中文“四十二”、十进制 `42`、十六进制 `2A`，它的大小没有改变。

数值本身没有“十六进制内存”或“二进制颜色”。进制是书写和阅读数值的方法，不是数值的固有属性。

### 进制写法：用哪些数字记号表示数值

进制（Radix 或 Base）规定每一位可以使用哪些数字，以及相邻两位之间的权重倍数：

| 进制 | 可用数字 | 常见前缀 | 嵌入式中的用途 |
| --- | --- | --- | --- |
| 二进制 | `0`、`1` | `0b` | 观察单个位和字段 |
| 八进制 | `0`～`7` | `0o` | 部分语言、权限或遗留资料 |
| 十进制 | `0`～`9` | 通常无 | 人类日常数值、计数和物理量 |
| 十六进制 | `0`～`9`、`A`～`F` | `0x` | 地址、寄存器、字节和位掩码 |

前缀不是数值的一部分，而是告诉读者后面的数字采用什么进制。项目中的示例使用 `0b`、`0o` 和 `0x`，避免只写一串数字让人猜测。

### 位模式：有限个位置上的 0 和 1

位模式（Bit Pattern）不仅包含每一位是 `0` 还是 `1`，还包含位宽。例如：

```text
0010 1010   # 8 位模式
0000 0000 0010 1010   # 16 位模式
```

两者按无符号整数解释都可以表示 `42`，但它们不是相同宽度的位模式。位宽会影响：

- 可以表示的范围。
- 最高位的位置。
- NOT 和移位操作的结果。
- 数据占用的 bit 数；当位宽是 8 的倍数时，也影响占用字节数。

因此，“把 `0xFF` 转成二进制”仍然缺少一个问题：你想看 8 位、16 位，还是其他宽度？

## 位权：所有进制转换的共同原理

### 通用公式

一个 R 进制整数的每一位都有位权。若从最右侧最低位开始编号为 `0`，数字为 `d_i`，则数值为：

```text
value = d₀ × R⁰ + d₁ × R¹ + d₂ × R² + ...
```

其中：

- `R` 是进制，例如二进制为 `2`，十六进制为 `16`。
- `d_i` 是第 i 位的数字，必须小于 `R`。
- 最右侧位的权重是 `R⁰ = 1`。

### 十六进制 `0x2A` 为什么是十进制 42

十六进制数字 `A` 表示十进制 `10`：

```text
0x2A = 2 × 16¹ + 10 × 16⁰
     = 2 × 16  + 10 × 1
     = 42
```

### 二进制 `0b00101010` 为什么也是 42

只把为 `1` 的位权相加：

```text
位编号      7 6 5 4 3 2 1 0
位值        0 0 1 0 1 0 1 0
位权      128 64 32 16 8 4 2 1
```

因此：

```text
0b00101010 = 32 + 8 + 2 = 42
```

这也是手工检查转换结果最可靠的方法：不要再调用另一段相同逻辑的代码，而是挑选少量为 `1` 的位，独立相加。

## 为什么十六进制特别适合观察位模式

因为 `16 = 2⁴`，一个十六进制数字恰好对应 4 个二进制位，这 4 位也称一个半字节（Nibble）：

| 二进制 | 十六进制 | 二进制 | 十六进制 |
| --- | --- | --- | --- |
| `0000` | `0` | `1000` | `8` |
| `0001` | `1` | `1001` | `9` |
| `0010` | `2` | `1010` | `A` |
| `0011` | `3` | `1011` | `B` |
| `0100` | `4` | `1100` | `C` |
| `0101` | `5` | `1101` | `D` |
| `0110` | `6` | `1110` | `E` |
| `0111` | `7` | `1111` | `F` |

例如：

```text
0010 1010
  2    A
```

所以 `0b00101010` 可以按每 4 位直接写成 `0x2A`，不需要先转成十进制。反过来也一样：把每个十六进制数字替换成 4 位二进制即可。

::: tip 前导零不是“没有意义”
从纯数值看，`0x2A`、`0x02A` 和 `0x002A` 都等于 42；从固定宽度展示看，前导零能告诉读者当前按多少位观察。例如 `0x2A` 常用于 8 位显示，`0x002A` 常用于 16 位显示。
:::

## 位模式本身不决定有符号还是无符号

考虑 8 位模式：

```text
1111 1111
```

### 按无符号整数解释

无符号整数（Unsigned Integer）把所有位都用于表示非负大小：

```text
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255
```

所以它是 `255`。

N 位无符号整数范围为：

```text
0 ～ 2ᴺ - 1
```

例如 8 位范围是 `0`～`255`。

### 按二进制补码有符号整数解释

二进制补码（Two's Complement）把最高位参与负数编码。对一个已经得到的 N 位无符号位模式 `U`：

```text
如果 U < 2ᴺ⁻¹：signed = U
否则：          signed = U - 2ᴺ
```

对 8 位 `1111 1111`：

```text
U = 255
signed = 255 - 256 = -1
```

所以同一组 8 位既可以解释为无符号 `255`，也可以解释为补码有符号 `-1`。位没有变化，变化的是解释规则。

N 位补码有符号整数范围为：

```text
-2ᴺ⁻¹ ～ 2ᴺ⁻¹ - 1
```

例如 8 位范围是 `-128`～`127`。负方向比正方向多一个值，因为零只需要一种编码。

完整的负数构造、符号扩展和范围推导见下一篇 [二进制补码与有符号整数范围](./twos-complement-signed-range)。

## 怎样把负数写成固定位宽补码

如果负数 `x` 能放进 N 位补码范围，其无符号位模式可以通过下面的公式得到：

```text
U = 2ᴺ + x
```

例如把 `-42` 写成 8 位补码：

```text
U = 256 + (-42)
  = 214
  = 0xD6
  = 0b11010110
```

反向核对：

```text
214 - 256 = -42
```

常见的“逐位取反再加一”也能得到相同结果，但上面的公式更直接说明：N 位补码实际上是在模 `2ᴺ` 的范围内保存位模式。

## 截断：只保留低 N 位意味着什么

固定宽度硬件或算法常写成“结果保留低 N 位”。数学上可以表达为：

```text
result = value modulo 2ᴺ
```

对非负整数，也可以理解为与 N 位全 1 掩码进行 AND：

```text
result = value AND (2ᴺ - 1)
```

### 8 位左移示例

将 8 位 `0x81` 左移 1 位：

```text
原始       1000 0001
左移      1 0000 0010
保留 8 位   0000 0010
结果           0x02
```

最左侧的 `1` 超出 8 位边界并被舍弃。只给出 `0x02` 而不说明位宽和截断，会让读者误以为计算少了一位。

::: warning 输入越界与运算截断不是一回事
工具会拒绝把十进制 `256` 当作合法 8 位输入，因为静默改成 `0` 可能隐藏工程错误；但选择 8 位左移时，工具按照明确的固定宽度规则保留低 8 位，并显示截断警告。
:::

## 看到一串数据时应该先问什么

假设文档、调试器或日志显示：

```text
FF 80 2A 00
```

在解释前至少确认：

1. 这是十六进制文本，还是四个真实字节的可视化？
2. 每个字段是 8 位，还是多个字节组成一个整数？
3. 字段按无符号还是补码有符号解释？
4. 多字节整数采用什么字节序？
5. 某些位是否是相互独立的标志和位域，而不是一个整体整数？

本文解决前三个问题的基础。字节序、字符编码和寄存器位域会在首批后续文章中分别说明。

## 常见错误与排查

| 现象或说法 | 问题在哪里 | 正确检查方法 |
| --- | --- | --- |
| “`0xFF` 就是 255” | 缺少位宽和解释方式；8 位补码也可读作 -1 | 先确认位宽和 signed/unsigned |
| “十六进制比二进制更接近硬件” | 两者只是同一位模式的不同写法 | 按每个十六进制数字对应 4 位二进制转换 |
| “前导零都可以删除” | 数值不变，但固定位宽信息可能丢失 | 在寄存器和协议字段中按约定位宽显示 |
| “负数写成 `-0x01` 就是一字节 `FF`” | 负号表达数学负数，`FF` 是 8 位模式；工具和语言语法可能不同 | 明确输入规则，再按 `2ᴺ + x` 求位模式 |
| “左移就是乘以 2，永远不会变小” | 固定位宽会舍弃高位 | 同时检查未截断结果和 N 位掩码 |
| “看到两个字节就能确定一个整数” | 还缺少字段边界、signedness 和字节序 | 查协议或数据手册对字段的正式定义 |
| “地址 `0x20000000` 有 8 个字节” | 8 个十六进制数字是 32 bit，即 4 byte | 每 2 个十六进制数字对应 1 byte |

## 平台与语言差异

### JavaScript / TypeScript

普通 JavaScript `number` 的位运算会采用 32 位整数语义，不适合直接实现 64 位寄存器工具。EmbedAtlas 的转换器使用 `BigInt` 保存整数，并通过 ECMAScript 定义的 `BigInt.asUintN` 和 `BigInt.asIntN` 建立固定宽度解释。

### C 和 C++

C/C++ 表达式还涉及具体整数类型、整数提升、转换规则和溢出行为。`uint8_t` 对象参与表达式时，不代表整个表达式一定始终以 8 位执行。本文的固定宽度数学模型用于理解位模式，不应直接替代语言标准和编译器规则。

首批文章《C 定宽整数、提升与溢出边界》会专门连接这两层概念。

## 自测

### 题目

1. `0xA5` 对应哪 8 个二进制位？
2. 8 位 `0x80` 按无符号和补码有符号分别是多少？
3. 为什么 8 位正数 `256` 越界？
4. `0x1234` 至少需要多少 bit？如果作为完整字节保存，需要多少 byte？
5. 8 位 `0xF0` 左移 1 位并只保留低 8 位，结果是什么？

### 答案

1. `0b10100101`，因为 `A` 对应 `1010`，`5` 对应 `0101`。
2. 无符号为 `128`；8 位补码有符号为 `128 - 256 = -128`。
3. 8 位无符号最大值是 `2⁸ - 1 = 255`。
4. 4 个十六进制数字对应 `4 × 4 = 16 bit`，即 `2 byte`。
5. `1111 0000` 左移得到 `1 1110 0000`，舍弃超出位宽的最高位后为 `1110 0000`，即 `0xE0`。
