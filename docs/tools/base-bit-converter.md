# 进制与位运算转换器需求规格

## 基本信息

- 工具名称：进制与位运算转换器
- 英文名称：Base and Bitwise Converter
- 工具标识：`base-bit-converter`
- 所属分类：数据表示与转换
- 目标版本：v0.1.0
- 状态：规格已定义，待实现

## 用户问题

嵌入式开发经常需要把寄存器值、协议字段和位掩码在二进制、八进制、十进制与十六进制之间转换，并检查 AND、OR、XOR、NOT 和移位结果。手工换算或临时脚本容易忽略位宽、最高位符号和溢出截断。

本工具把“数学整数”“固定宽度位模式”和“有符号解释”分层展示，让使用者不只得到结果，还能看懂为什么同一个 `0xFF` 在 8 位下既可以表示无符号数 `255`，也可以表示补码有符号数 `-1`。

## 范围

### 支持

- 二、八、十、十六进制整数输入和互相转换。
- 8、16、32、64 位固定宽度，默认 8 位。
- 同时显示无符号十进制值和二进制补码有符号值。
- AND、OR、XOR、NOT、左移、逻辑右移和算术右移。
- 按位宽补齐的二进制、八进制和十六进制结果。
- 从最高位到最低位显示位编号和值。
- 输入随修改即时重新计算；错误时保留输入并指出位置和原因。
- 所有计算完全在浏览器本地完成。

### 不支持

- 小数、科学计数法、浮点数和 IEEE 754 解析。
- 二、八、十、十六以外的任意进制。
- 大于 64 位或用户自定义位宽。
- 加、减、乘、除等算术计算。
- 循环移位、位反转、字节交换和大小端转换。
- C/C++ 实现定义行为、CPU 标志位或特定芯片寄存器语义模拟。

这些能力分别属于后续的浮点数、大小端、位域和 MCU 工具，不在第一个工具中提前混合。

## 输入规则

### 通用语法

1. 输入前后的 ASCII 空白会被忽略，输入中间的空白不允许。
2. 数字中的 `_` 可以作为可读性分隔符，例如 `0xFF_FF`；不能位于开头、结尾或连续出现。
3. 二进制、八进制和十六进制可省略前缀，也可分别使用 `0b`、`0o`、`0x`；前缀必须与选择的进制一致。
4. 十六进制字母 `A`～`F` 不区分大小写，结果统一使用大写。
5. 负号只允许用于十进制输入。非十进制输入表示原始位模式，不接受 `-0x01` 等写法。
6. 正数有效范围为 `0`～`2^N - 1`；负数有效范围为 `-2^(N-1)`～`-1`，其中 `N` 是所选位宽。
7. 单个输入框最多接受 128 个字符，避免粘贴异常大文本造成无意义解析。

### 字段

| 字段 | 类型 | 单位/格式 | 有效范围 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 位宽 `bitWidth` | 枚举 | bit | 8、16、32、64 | 8 | 决定允许范围、补零长度和运算截断位置 |
| 操作数 A `operandA` | 字符串 | 所选进制整数 | 见通用语法 | `0x2A` | 必填，转换模式和所有运算都使用 |
| A 的进制 `radixA` | 枚举 | 2、8、10、16 | 四个固定值 | 16 | 不使用不可靠的自动猜测 |
| 运算 `operation` | 枚举 | 转换、AND、OR、XOR、NOT、左移、逻辑右移、算术右移 | 固定集合 | 转换 | “转换”只展示 A 的多种表示 |
| 操作数 B `operandB` | 字符串 | 所选进制整数 | 见通用语法 | `0x0F` | AND、OR、XOR 时必填 |
| B 的进制 `radixB` | 枚举 | 2、8、10、16 | 四个固定值 | 16 | 仅在需要 B 时显示 |
| 移位量 `shiftCount` | 整数 | bit | `0`～`N-1` | 1 | 仅在三种移位操作中显示 |

## 输出

| 字段 | 类型 | 单位/格式 | 说明 |
| --- | --- | --- | --- |
| 固定位模式 `unsignedValue` | `bigint` | `0`～`2^N-1` | 所有表示和运算的统一内部值 |
| 二进制 `binary` | 字符串 | `0b` + 恰好 N 位 | 每 4 位可在界面分组，但复制值默认不含分隔符 |
| 八进制 `octal` | 字符串 | `0o` + `ceil(N/3)` 位 | 高位补零，便于固定宽度比较 |
| 无符号十进制 `unsignedDecimal` | 字符串 | 十进制 | 按 `0`～`2^N-1` 解释 |
| 有符号十进制 `signedDecimal` | 字符串 | 十进制 | 按 N 位二进制补码解释 |
| 十六进制 `hexadecimal` | 字符串 | `0x` + `N/4` 位大写数字 | 高位补零，例如 8 位值 `5` 显示为 `0x05` |
| 位列表 `bits` | 数组 | `{ index, value }[]` | 从 `N-1` 到 `0`，用于位可视化 |
| 截断提示 `wasTruncated` | 布尔值 | 是/否 | 左移丢弃高位时为真，其他操作通常为假 |

输出值使用字符串传给界面，避免 64 位整数经过 JavaScript `number` 后损失精度。

## 算法与依据

### 固定宽度规范化

设位宽为 `N`，掩码为：

```text
mask = 2^N - 1
```

输入解析为数学整数 `x` 后，其 N 位无符号位模式为：

```text
unsigned = x modulo 2^N
```

只有已通过输入范围检查的值才能进入规范化步骤。输入超出范围时必须报错，不能静默截断；位运算结果则按固定宽度截断，并在左移丢失高位时给出提示。

N 位补码有符号解释为：

```text
signed = unsigned < 2^(N-1)
  ? unsigned
  : unsigned - 2^N
```

实现使用 `BigInt`，固定宽度转换语义与 ECMAScript 的 [`BigInt.asUintN`](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-bigint.asuintn) 和 [`BigInt.asIntN`](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-bigint.asintn) 保持一致。不能使用普通 JavaScript `number` 位运算代替，因为那会先转换为 32 位整数，无法正确覆盖 64 位模式。

### 位运算

设 `A`、`B` 均为已经规范化的 N 位无符号位模式：

| 操作 | 结果位模式 | 说明 |
| --- | --- | --- |
| AND | `(A & B) & mask` | 两位都为 1 时结果为 1 |
| OR | `(A \| B) & mask` | 任一位为 1 时结果为 1 |
| XOR | `(A ^ B) & mask` | 两位不同时结果为 1 |
| NOT | `(~A) & mask` | 只反转所选位宽内的位 |
| 左移 | `(A << shiftCount) & mask` | 低位补 0，超出 N 位的高位丢弃 |
| 逻辑右移 | `A >> shiftCount` | A 按无符号值处理，高位补 0 |
| 算术右移 | `asIntN(N, A) >> shiftCount` 后再转回 N 位模式 | 高位补符号位 |

`BigInt` 不支持无符号右移运算符 `>>>`；ECMAScript 规范明确该组合会抛出 `TypeError`。本工具的逻辑右移通过“先取得非负的 N 位无符号值，再使用 `>>`”实现。

### 舍入、精度、字节序与位序

- 仅处理整数，不发生浮点舍入。
- 所有内部整数使用 `BigInt`，64 位范围内保持精确。
- 本工具只解释数值和位模式，不解释内存字节序。
- 位列表左侧为最高有效位 `N-1`，右侧为最低有效位 `0`。
- 移位量达到或超过位宽时拒绝输入，不套用 JavaScript Number 的“对 32 取模”规则。

## 错误处理

核心逻辑返回带错误代码的结构化结果，Vue 组件负责把代码映射为中文提示；不得以 `NaN`、空字符串或异常堆栈作为用户结果。

| 错误代码 | 条件 | 用户提示 |
| --- | --- | --- |
| `EMPTY_INPUT` | 必填输入为空 | 请输入一个整数。 |
| `INVALID_DIGIT` | 出现当前进制不允许的字符 | 字符“{char}”不能用于 {radix} 进制，位置 {position}。 |
| `INVALID_SEPARATOR` | `_` 位于开头、结尾或连续出现 | 下划线只能放在两个数字之间。 |
| `PREFIX_BASE_MISMATCH` | 前缀与选择的进制不一致 | 输入前缀表示 {prefixRadix} 进制，但当前选择的是 {selectedRadix} 进制。 |
| `NEGATIVE_NON_DECIMAL` | 非十进制输入带负号 | 负数请使用十进制输入；十六进制等格式用于输入原始位模式。 |
| `OUT_OF_RANGE` | 输入超出当前位宽允许范围 | 该值超出 {bitWidth} 位范围：正数最大为 {maxUnsigned}，负数最小为 {minSigned}。 |
| `MISSING_SECOND_OPERAND` | 二元运算缺少 B | 当前运算还需要操作数 B。 |
| `INVALID_SHIFT_COUNT` | 移位量不是整数或不在 `0`～`N-1` | 移位量必须是 0 到 {maxShift} 之间的整数。 |
| `INPUT_TOO_LONG` | 输入超过 128 个字符 | 输入过长；本工具最多处理 64 位整数。 |

## 测试向量

以下结果可以从逐位运算、2 的幂和补码定义独立推导；固定宽度有符号/无符号转换还应与 ECMAScript 规范算法交叉核对。

| 场景 | 输入 | 预期输出 | 依据 |
| --- | --- | --- | --- |
| 典型转换 | N=8，A=`0x2A` | bin=`0b00101010`，oct=`0o052`，unsigned=`42`，signed=`42`，hex=`0x2A` | `42 = 32 + 8 + 2` |
| 零值 | N=8，A=`0`，radix=10 | bin=`0b00000000`，hex=`0x00`，signed=`0` | 零的固定宽度表示 |
| 最大 8 位无符号值 | N=8，A=`255` | hex=`0xFF`，unsigned=`255`，signed=`-1` | `2^8-1` 和补码定义 |
| 最小 8 位有符号值 | N=8，A=`-128` | hex=`0x80`，unsigned=`128`，signed=`-128` | `-2^7` |
| 负一规范化 | N=16，A=`-1` | hex=`0xFFFF`，unsigned=`65535`，signed=`-1` | ECMAScript `asUintN` / `asIntN` 算法 |
| 64 位精度 | N=64，A=`0xFFFFFFFFFFFFFFFF` | unsigned=`18446744073709551615`，signed=`-1` | `2^64-1` |
| AND | N=8，A=`0xA5`，B=`0x0F` | result=`0x05` | `10100101 AND 00001111` |
| OR | N=8，A=`0xA5`，B=`0x0F` | result=`0xAF` | `10100101 OR 00001111` |
| XOR | N=8，A=`0xA5`，B=`0x0F` | result=`0xAA` | `10100101 XOR 00001111` |
| NOT | N=8，A=`0x0F` | result=`0xF0` | 8 位内逐位反转 |
| 左移截断 | N=8，A=`0x81`，shift=1 | result=`0x02`，`wasTruncated=true` | `1_00000010` 舍弃第 8 位 |
| 逻辑右移 | N=8，A=`0x80`，shift=1 | result=`0x40` | 高位补 0 |
| 算术右移 | N=8，A=`0x80`，shift=1 | result=`0xC0`，signed=`-64` | 符号位补 1 |
| 合法分隔符 | N=16，A=`0xFF_FF` | result=`0xFFFF` | 输入语法要求 |
| 非法数字 | radix=2，A=`102` | `INVALID_DIGIT`，字符 `2`，位置 3 | 二进制数字集合 |
| 前缀不匹配 | radix=10，A=`0x10` | `PREFIX_BASE_MISMATCH` | 输入语法要求 |
| 超出范围 | N=8，A=`256` | `OUT_OF_RANGE` | 8 位正数最大为 255 |
| 非法移位量 | N=8，shift=8 | `INVALID_SHIFT_COUNT` | 允许范围为 0～7 |

交互要求：

- 适合即时计算，因此输入合法时实时更新，不增加“计算”按钮。
- 输入错误显示在对应字段下方，并通过 `aria-describedby` 与输入关联。
- 错误出现后不清空其他字段；修正后立即恢复结果。
- 二元操作并排展示 A、B 和结果的位模式，帮助理解逐位关系。
- 复制按钮必须说明复制的是带前缀还是纯数字，并提供可感知的成功反馈。
- 窄屏时字段和结果纵向排列，位列表允许在自身区域横向滚动，不让整个页面溢出。
- 可只用键盘选择字段、输入、复制、载入示例和重置。

## 隐私与安全

- 数据完全在浏览器本地处理，不发送到服务器。
- 不支持文件上传。
- 每个输入框限制为 128 个字符，实际有效数值不超过 64 位。
- 不执行用户输入，不使用 `eval`，也不把输入拼接为 JavaScript 源码。
- 工具用于换算和学习，不替代芯片手册、协议标准或编译器对目标类型的实际定义。
