# HEX、ASCII 与字符串转换器需求规格

## 1. 用户问题

嵌入式工程师需要在可读文本和原始字节之间转换，并明确回答：

- 字符串采用 ASCII 还是 UTF-8？
- `41 42` 表示两个字节，还是四个字符？
- 中文、表情等字符实际占多少 byte？
- 一段 HEX 是否为合法的目标编码？

## 2. 范围

首版支持：

- UTF-8 文本编码为 HEX 字节。
- ASCII 文本编码为 HEX 字节；非 ASCII 字符明确报错。
- HEX 字节按 UTF-8 严格解码；非法序列明确报错，不自动替换。
- HEX 字节按 ASCII 解码；大于 `0x7F` 的字节明确报错。
- 显示 HEX、十进制字节、可打印 ASCII 预览和 byte 数。
- 输入仅在本地浏览器处理，最多 4096 byte。

首版不支持：

- GBK、Big5、Shift_JIS 等旧编码。
- 文件上传、自动猜测编码和 BOM 自动删除。
- C 转义序列、Base64 或 URL 编码。

## 3. HEX 输入语法

- 十六进制不区分大小写。
- 支持连续形式 `414243`。
- 支持空格、换行、逗号、分号、冒号、短横线和下划线分隔。
- 支持每组可选的 `0x` 前缀，例如 `0x41, 0x42`。
- 移除允许的前缀和分隔符后，必须得到偶数个十六进制数字。
- 不接受通配符、负号或静默补零。

## 4. 编码语义

- ASCII 只接受 Unicode 码点 `U+0000`～`U+007F`，一字符对应一 byte。
- UTF-8 使用浏览器标准 `TextEncoder` 编码。
- 编码前拒绝未配对的 UTF-16 代理项，避免被静默替换为 `U+FFFD`。
- UTF-8 解码使用 fatal 模式，非法、截断或非最短序列均报错。
- `NUL`、换行等控制字符允许存在，但 ASCII 预览显示占位符，不执行控制行为。

## 5. 错误模型

- 空输入。
- 非法 HEX 字符及其位置。
- 孤立 `0x` 前缀。
- 奇数个十六进制数字。
- 超出 4096 byte。
- ASCII 模式中的非 ASCII 字符或字节。
- UTF-8 非法字节序列。
- 文本中的未配对 UTF-16 代理项。

## 6. 核心验收向量

| 操作 | 输入 | 预期 |
| --- | --- | --- |
| ASCII 编码 | `ABC` | `41 42 43` |
| UTF-8 编码 | `中` | `E4 B8 AD` |
| UTF-8 编码 | `😀` | `F0 9F 98 80` |
| UTF-8 解码 | `E4 B8 AD` | `中` |
| UTF-8 解码 | `C0 AF` | 非法 UTF-8 |
| ASCII 解码 | `80` | 超出 ASCII |
| HEX 解析 | `0x41, 42:43` | `41 42 43` |
| HEX 解析 | `ABC` | 奇数个数字 |

## 7. 验收条件

- [ ] 核心逻辑不依赖 Vue 或 DOM。
- [ ] 正常、边界和非法向量都有单元测试。
- [ ] 非法 UTF-8 不显示替换字符冒充成功。
- [ ] 桌面和 390px 窄屏无整页横向溢出。
- [ ] 可复制结果、载入示例和重置。
- [ ] 页面与字符编码、HEX 文本原理文章互链。
- [ ] 页面明确说明本地处理和输入上限。
