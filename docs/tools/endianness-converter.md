# 大小端与字节交换转换器需求规格

## 1. 用户问题

嵌入式工程师从内存窗口、寄存器、抓包或串口日志中拿到一组 byte 时，需要快速判断它按大端或小端解释分别是什么数值；反过来，也需要把一个无符号整数编码成协议要求的 byte 顺序，而不是临时手算或写一次性脚本。

## 2. 首版范围

- 严格解析 1～8 byte 的 HEX 序列，分别显示大端与小端无符号数值。
- 将 1、2、4 或 8 byte 宽度的无符号整数编码为大端和小端 byte 序列。
- 数值输入支持十进制或十六进制；显示结果始终保留完整字段宽度。
- 显示完整字节反转结果，并明确它不等于所有协议中的“字交换”规则。
- 所有输入只在当前浏览器本地处理。

首版不支持浮点数、带符号补码、PDP-endian、16-bit word 内部与 word 之间的混合交换、文件上传或自动猜测协议格式。

## 3. 输入与输出

### byte 序列转整数

- 输入：1～8 个 HEX byte，支持空白、逗号、分号、冒号、下划线和连字符分隔，也接受逐 byte `0x` 前缀。
- 输出：规范 HEX、完整反转序列、byte 数、大端无符号十六进制/十进制、小端无符号十六进制/十进制。

### 整数转 byte 序列

- 输入：十进制或十六进制非负整数；宽度为 1、2、4 或 8 byte。
- 输出：按字段宽度补零后的数值、大端 byte 序列和小端 byte 序列。

## 4. 算法

大端解释从左到右执行 `value = value × 256 + byte`。小端解释使用相同算法读取反转后的 byte 序列。整数编码从最低有效 byte 开始逐次取 `value & 0xFF`，小端按取得顺序排列，大端反向排列。

全部整数运算使用 JavaScript `BigInt`，避免 64 bit 值经过 `Number` 丢失精度。

## 5. 错误模型

- 空输入。
- HEX 中包含非法字符、空 `0x` 前缀或奇数个 HEX 数字。
- byte 序列超过 8 byte。
- 整数包含与所选进制不匹配的字符、为负数或超过选定宽度。

错误必须包含稳定代码；中文提示由语言资源层生成。

## 6. 测试向量

| 场景 | 输入 | 预期结果 |
| --- | --- | --- |
| 32 bit 典型序列 | `12 34 56 78` | 大端 `0x12345678`，小端 `0x78563412` |
| 16 bit 协议字段 | `34 12` | 大端 `0x3412`，小端 `0x1234` |
| 64 bit 精度 | `01 23 45 67 89 AB CD EF` | 大端 `0x0123456789ABCDEF` |
| 整数编码 | HEX `12345678`，4 byte | 大端 `12 34 56 78`，小端 `78 56 34 12` |
| 边界 | 十进制 `255`，1 byte | `FF` |
| 越界 | 十进制 `256`，1 byte | `VALUE_OUT_OF_RANGE` |
