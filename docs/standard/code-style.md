# 代码规范

本规范会随脚手架和自动化工具落地而补充。能够自动检查的格式问题应交给格式化工具，人主要审阅正确性、边界和可读性。

## 1. 通用原则

- 优先写小而清楚的纯函数。
- 名称表达领域含义，不使用模糊缩写。
- 显式处理错误，不静默修正可能改变结果的输入。
- 避免提前抽象；至少出现稳定的重复模式后再提取通用层。
- 一个模块只承担一个主要职责。
- 注释解释原因、规则和陷阱，代码本身表达步骤。

## 2. TypeScript

- 启用严格类型检查。
- 避免 `any`；必须使用时写明边界和原因。
- 对工具输入和输出定义命名类型，不传递含义不清的数组。
- 可为空、缺失和无效是不同状态时，不使用同一个值混淆表达。
- 领域函数优先返回结构化结果或明确错误类型。
- 单位写入名称，例如：

```ts
const peripheralClockHz = 72_000_000;
const frameTimeUs = 86.8;
```

不要使用：

```ts
const clock = 72000000;
const time = 86.8;
```

## 3. Vue 组件

- 组件负责输入、显示和交互，不直接承载复杂计算公式。
- 计算逻辑放在 `site/lib/tools/` 的普通 TypeScript 模块中。
- Props、事件和公共数据结构必须有类型。
- 一个工具内部的小组件保持局部，不急于加入全局组件库。
- 错误信息应说明如何修正输入，不只显示“计算失败”。

## 4. 嵌入式 C/C++ 示例

- 明确示例使用的语言标准、芯片系列和依赖环境。
- 优先使用 `<stdint.h>` 中的定宽整数类型表达协议字段。
- 寄存器、位掩码和魔数必须说明来源。
- 与硬件相关的等待、超时、并发和 `volatile` 使用必须解释原因。
- 示例省略错误处理时必须明确说明，不能让读者误以为可直接用于生产。
- 伪代码必须标记为伪代码，不使用可编译代码块造成误解。

## 5. 命名

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| TypeScript 变量与函数 | `camelCase` | `calculateFrameTime` |
| TypeScript 类型与 Vue 组件 | `PascalCase` | `CrcParameters` |
| 常量 | 语义稳定时使用 `UPPER_SNAKE_CASE` | `MAX_DATA_BITS` |
| 文件和 URL 标识 | `kebab-case` | `uart-frame-time.ts` |
| 布尔值 | 使用 `is`、`has`、`can`、`should` | `isReflected` |
| 带单位数值 | 名称包含单位 | `timeoutMs`、`frequencyHz` |

## 6. 数值与协议代码

- 明确十进制、十六进制和二进制的显示意图。
- 位运算要考虑 JavaScript 的 32 位有符号转换行为。
- 超过安全整数范围时明确采用 `BigInt` 或字符串。
- 浮点计算说明显示精度与内部精度的区别。
- CRC、校验和等算法必须包含完整模型参数和已知检查值。
- 字节序转换明确“输入字节顺序”和“数值解释”，避免只写“反转”。

## 7. 自动化

项目初始化后应通过配置统一：

- 格式化。
- TypeScript 类型检查。
- ESLint 或等效静态检查。
- 单元测试。
- VitePress 构建。

具体命令落地后更新 `docs/development/getting-started.md`。
