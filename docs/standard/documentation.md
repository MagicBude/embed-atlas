# 知识与项目文档规范

## 1. 语言

- 主要使用简体中文。
- 专业术语首次出现时写作“中文名称（English Term，缩写）”。
- 后文可以使用业内通用缩写，但不能假设初学者认识未定义缩写。
- 句子尽量直接，避免空泛的宣传语和不必要的网络表达。
- 不用“显然”“众所周知”“非常简单”等表达评价读者。

## 2. 标题与结构

- 每个文件只有一个一级标题。
- 标题按层级递进，不从二级直接跳到四级。
- 标题描述内容，不使用大量重复的“介绍”“说明”。
- 长文章开头说明解决的问题和前置知识。
- 一个段落集中表达一个主要意思。

## 3. 代码和数值

- 代码块标注语言。
- 可运行代码与伪代码明确区分。
- 示例注明平台、依赖和关键版本差异。
- 十六进制使用 `0x` 前缀，二进制使用 `0b` 前缀。
- 数值与单位之间的格式保持一致，例如 `72 MHz`、`115200 bit/s`。
- `KB`、`KiB`、`kb` 等容易混淆的单位必须按实际含义使用。

## 4. 图片和图表

- 图片必须有替代文本和简短说明。
- 优先使用可以版本管理的 SVG、Mermaid 或源文件。
- 截图只保留必要界面，避免包含账号、设备序列号或项目机密。
- 引用外部图片必须确认授权并注明来源。
- 图中颜色不能是表达区别的唯一方式。

## 5. 来源和版权

优先级建议：

1. 国际标准或协议规范。
2. 芯片、内核、RTOS 或工具的官方文档。
3. 官方示例和公开源码。
4. 高质量技术书籍、论文和可信社区资料。

要求：

- 关键参数、协议定义和不直观结论应给出来源。
- 标明访问的是哪个版本或文档修订版。
- 用自己的语言解释，不复制大段原文。
- 引用短句时使用引号或引用块并标注链接。
- 无法核实的经验必须标为“工程建议”或“待验证”。

## 6. 事实与建议

文章应帮助读者区分：

- **规范要求**：标准或硬件明确规定。
- **实现事实**：某个已注明版本的实现行为。
- **工程建议**：基于权衡的推荐做法。
- **示例选择**：为便于教学采用，不代表唯一方案。

不要把个人偏好写成协议或标准要求。

## 7. 链接

- 优先链接到稳定的官方文档页面。
- 内部链接使用相对路径，方便预览和迁移。
- 链接文字描述目标内容，不使用大量“点击这里”。
- 删除或移动页面前提供替代入口，稳定发布后避免随意改变 URL。

## 8. 文章审阅

- [ ] 目标读者和范围清楚。
- [ ] 关键术语首次出现时得到解释。
- [ ] 公式变量、数值和单位准确。
- [ ] 示例代码的适用环境明确。
- [ ] 常见错误与边界情况有说明。
- [ ] 关键事实存在可靠来源。
- [ ] 相关工具和文章已经互相链接。
- [ ] 没有复制未授权内容或泄露敏感信息。
