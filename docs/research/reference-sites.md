# 参考网站研究

> 调研日期：2026-08-23
> 调研目的：学习信息组织、工具范围、页面结构与交互模式，不复制任何网站的代码、文章、视觉资产或品牌设计。

## 1. 调研范围

本轮选择五个与 EmbedAtlas 方向互补的网站：

- [Embedwise](https://embedwise.com/)：嵌入式工程计算器与配套技术解释。
- [IRQKit](https://irqkit.com/)：数量较多的开发者与嵌入式在线工具。
- [嵌入式调试工具箱](https://emb.edaget.com/)：中文、工作台式的嵌入式工具集合。
- [Embed Lab](https://embed.org.in/)：围绕开发板、文档、语言、项目和社区组织知识。
- [TestBench.tools](https://testbench.tools/)：测试测量、工业控制和嵌入式计算工具。

其中 IRQKit 的首页、筛选控件与 CRC 工具，以及嵌入式调试工具箱的首页和模块导航经过了实际页面交互检查；其他站点结合其首页、工具页和公开页面结构进行核对。

## 2. 总体对比

| 网站 | 主要定位 | 最值得学习 | 需要避免 |
| --- | --- | --- | --- |
| Embedwise | 嵌入式工程计算器 | 工具、公式、MCU 预设、代码示例和常见错误形成闭环 | 单页解释很长，需要为只想快速计算的用户保留清晰入口 |
| IRQKit | 大型在线工具目录 | 搜索、类型/领域/技术多维筛选、示例按钮、多种结果格式 | 首页过长、标签数量过多，通用开发工具可能稀释嵌入式定位 |
| 嵌入式调试工具箱 | 中文单页工作台 | 固定侧栏、模块分组、快速搜索、通信调试与转换工具统一入口 | 单页 `#` 导航不利于深链接、搜索收录和独立分享；侧栏容易拥挤 |
| Embed Lab | 嵌入式学习与项目社区 | 按文档、语言、项目、社区和开发板提供多种学习入口 | 内容和工具的关联不够突出，早期空分类会削弱可信度 |
| TestBench.tools | 工业与测试测量工具 | 搜索优先、分类计数、即时结果、参考向量、现场笔记和隐私说明 | 范围过宽时分类可能碎片化，同族工具拆分过多会增加选择成本 |

## 3. 工具范围

### 3.1 协议与通信

代表工具包括：

- UART 帧时间、波特率误差和寄存器参数。
- I2C 地址转换、上拉电阻计算。
- SPI 模式、时钟分频。
- CAN 与 MCP2515 位时序。
- Modbus RTU 时间、功能码、地址转换、报文生成与解析。
- RS-485 偏置与终端计算。
- NMEA、UBX、MC Protocol、LS XGT 等报文或校验工具。

借鉴点：不能只给最终数字，应同时显示线上的字节顺序、实际误差、寄存器字段和协议规定。

### 3.2 数据转换与表示

代表工具包括：

- 二、八、十、十六进制转换。
- 位运算、位域提取和二进制可视化。
- HEX、ASCII、Binary 与文本互转。
- 补码、大小端、字交换。
- IEEE 754 浮点数和 Modbus ABCD/CDAB/BADC/DCBA 字序。
- 定点数 Q 格式。
- C 结构体对齐与填充可视化。

借鉴点：转换工具应同时呈现“数值含义”和“内存/线路字节序”，避免把字节反转误称为数值转换。

### 3.3 校验、CRC 与数据完整性

代表工具包括：

- XOR、SUM、LRC 等简单校验和。
- CRC-8、CRC-16、CRC-32 和 CRC-32C。
- 自定义宽度、Poly、Init、RefIn、RefOut、XorOut。
- CRC 模型识别与标准检查字符串 `123456789`。
- Modbus、NMEA、1-Wire 等协议预设。

借鉴点：CRC 页面应提供预设和高级参数两层界面，同时展示标准检查值、十六进制/十进制结果及大端/小端字节。

### 3.4 MCU、固件与时序

代表工具包括：

- 定时器 Prescaler、Period/ARR 和 PWM 参数。
- 看门狗超时。
- ADC 码值、电压、分辨率和 ENOB。
- 中断延迟、RTC 漂移、Flash 擦写寿命。
- Intel HEX、Motorola S-Record 与 BIN 转换。
- 固件 HEX 查看、C 数组生成。

借鉴点：MCU 工具可以逐步加入芯片族预设，但公式核心不能依赖单一厂商，预设只是参数层。

### 3.5 电路、传感器与电源

代表工具包括：

- 欧姆定律、分压、LED 限流、电阻色环和 SMD 编码。
- I2C 上拉、运放增益、RC 滤波和 555 定时器。
- NTC、PT100/PT1000、热电偶和传感器标定。
- 电池寿命、功耗、LDO、Buck、线损和回路负载。
- LoRa 空中时间、链路预算和发射功率换算。

借鉴点：计算结果应包含容差、误差或安全余量，而不是只返回理想值。

### 3.6 显示与文件工具

代表工具包括：

- RGB565 颜色选择与格式转换。
- 图片转 RGB565、单色位图或 LVGL 数组。
- TFT 带宽和帧率估算。
- CSV 波形查看、HEX 文件查看、TDMS 转换。

借鉴点：处理文件时默认在浏览器本地运行，明确显示文件大小限制和“不上传”说明。

### 3.7 浏览器硬件调试

中文嵌入式调试工具箱展示了以下方向：

- Web Serial 串口调试。
- Web Bluetooth 蓝牙调试。
- WebUSB / WebHID 调试。
- WebSocket 网络调试。
- 指令模板和批量发送。

这些功能有价值，但涉及浏览器兼容性、设备授权和更复杂的状态管理，暂时保留为远期方向，不进入最小版本。

## 4. UI 与交互研究

### 4.1 首页入口

可借鉴的组合：

1. 顶部使用一句清楚的中文定位，不使用空泛口号。
2. 首屏提供统一搜索框，支持搜索知识、工具、协议和芯片关键词。
3. 搜索框下提供“开始学习”和“打开工具箱”两个主要入口。
4. 展示少量常用工具，而不是一次铺满所有工具。
5. 按“学习路线”和“工程问题”分别组织内容。

IRQKit 和 TestBench.tools 的搜索优先模式适合工具较多时使用；Embed Lab 的多入口模式适合知识学习；中文工具箱的模块卡片适合快速认识能力范围。

### 4.2 工具目录

IRQKit 实际使用三类筛选维度：工具类型、工程领域和具体技术，并显示每个标签的工具数量。这种方式适合后期工具数量较多时使用。

EmbedAtlas 采用渐进策略：

- 工具少于约 12 个时，只使用搜索和一级分类。
- 工具增多后再增加协议、数据格式、MCU、硬件等标签。
- 不在第一版显示大量数量为零的分类。
- 每个工具卡片只显示名称、一句话用途、关键标签和是否已验证。

### 4.3 工具页面

综合 Embedwise、IRQKit 和 TestBench.tools，工具页面采用以下顺序：

```text
名称与一句话用途
    ↓
输入与预设
    ↓
实时或显式计算
    ↓
突出显示主结果
    ↓
十六进制、十进制、字节序等详细结果
    ↓
公式、参数和可复现示例
    ↓
C / C++ / Rust 等代码示例
    ↓
常见错误、FAQ 与关联知识
```

关键交互：

- 提供经过验证的“一键示例”。
- 复制操作给出明确的成功反馈。
- 输入旁边持续显示解析后的字节数或单位。
- 无效输入指出具体字符、位置和修改方法。
- 主结果突出，详细结果分层展示。
- 适合即时计算的工具随输入更新；耗时或文件操作使用明确按钮。
- 允许重置，但不在用户输入时突然清空其他字段。

### 4.4 知识页面

Embedwise 的工具页把解释、代码和错误案例放在计算器下方，学习闭环完整；Embed Lab 则提供按开发板、语言、项目和难度进入内容的方式。

EmbedAtlas 应当：

- 正文保持知识文章结构，不把工具说明伪装成文章。
- 文章中可嵌入工具的精简模式。
- 工具页链接完整原理文章。
- 按学习路线、知识分类、开发平台和搜索四种方式找到内容。
- 页面明确标识草稿、审阅中、已验证或已废弃。

## 5. 我们采用与不采用的设计

### 采用

- 中文优先、英文术语辅助。
- 统一搜索，知识与工具共同索引。
- 工具分类和标签，但按数量逐步启用。
- 浏览器本地计算和明确隐私说明。
- MCU/协议预设加自定义参数。
- 标准检查向量、参数表和中间结果。
- 一键示例、复制反馈、相关工具与文章。
- 原理、代码、常见错误和 FAQ 的教学闭环。
- 可分享的独立 URL，而不是所有工具放在单一 `#` 页面中。

### 不采用

- 第一版就展示几十个空分类。
- 把所有工具塞进一条永久展开的侧边栏。
- 只显示结果、不解释算法和单位。
- 为增加数量而重复制作通用开发工具。
- 依赖登录才能使用基础知识与工具。
- 默认上传固件、日志或用户文件。
- 复制其他网站的视觉风格、文章结构细节或品牌资产。

## 6. 对现有规划的影响

本轮调研没有推翻 VitePress、Vue、TypeScript 和静态优先的基础架构，但补充了三个产品层要求：

1. 信息架构必须同时支持学习、查阅和快速计算。
2. 工具模块必须支持预设、示例、详细结果、解释和验证状态。
3. 搜索、标签和侧栏应随内容数量逐步增强，不能在初期过度设计。
