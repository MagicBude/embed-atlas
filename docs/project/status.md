- 明确第一核心是“中文嵌入式知识库 + 在线工具箱”。
- 建立根目录治理文件和 `docs/` 文档体系。
- 建立总体架构、内容系统、工具系统和首个 ADR。
- 建立教材级注释、代码、文档和 Git 提交规范。

## 正在进行

- 人工审阅基础规划，确认范围、术语和技术方向。

## 下一步

按顺序执行，未确认上一项前不扩大范围：

1. 审阅并修订 Phase 0 文档。
2. 确定代码与内容的许可证方案。
3. 根据 ADR-0001 初始化 VitePress、Vue 和 TypeScript。
4. 建立首页、知识库和工具箱的空导航骨架。
5. 为第一个工具编写需求规格和验收用例。
6. 实现“进制与位运算转换器”的纯计算核心、测试和界面。

## 已确认决策

- 中文优先，首次出现的关键术语保留英文名称。
- 项目治理文档放在 `docs/`，正式站点内容计划放在 `site/`。
- 第一阶段使用静态网站，不引入账号、数据库和云端后端。
- 工具核心计算与 Vue 界面分离。
- 关键代码使用教材级注释，并以测试作为结果依据。

## 尚待确认

- 程序代码和知识内容分别采用哪一种许可证。
- 第一批 10 篇文章的准确选题与负责人。
- 网站视觉名称是否同时展示“EmbedAtlas”和“嵌入式图谱”。
- 首次公开部署使用 GitHub Pages 还是其他静态托管服务。

## 当前风险

- 早期分类过细会产生大量空页面。
- 工具数量增长过快会降低测试与解释质量。
- 不同资料对协议参数和术语的定义可能不一致，需要明确来源。
- “教材级注释”如果被理解为逐行解释，会造成噪声和维护负担；应遵守注释规范中的边界。
