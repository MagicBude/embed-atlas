# UI 与交互设计原则

## 1. 设计定位

视觉方向是“工程工作台的可靠感 + 知识图谱的清晰导航”，而不是复刻某个参考网站。

关键词：

- 清楚
- 可信
- 克制
- 高效
- 适合长时间阅读
- 对初学者友好

## 2. 视觉层级

- 主结果、页面标题和当前任务最突出。
- 参数说明、单位和状态紧邻对应控件。
- 高级选项默认折叠或放在第二层，不与常用输入竞争。
- 错误、警告、成功和普通信息不仅依赖颜色，还要配合文字或图标。
- 深色与浅色主题都保证代码、表格和输入框的对比度。
- 不用大量装饰性动画干扰工程输入。

具体颜色、字体和尺寸在网站原型阶段形成设计令牌，不在规划阶段提前锁死。

## 3. 标准工具页面

```text
┌──────────────────────────────────────┐
│ 工具名称、用途、验证状态、本地处理说明 │
├─────────────────┬────────────────────┤
│ 输入与预设       │ 主结果              │
│ 示例 / 重置      │ 详细格式 / 复制      │
├─────────────────┴────────────────────┤
│ 公式与参数 / 中间过程                 │
│ 常见错误 / 代码示例 / 关联知识         │
└──────────────────────────────────────┘
```

桌面端可以左右分栏，窄屏端按输入、主结果、详细解释顺序纵向排列。

## 4. 输入交互

- 每个输入必须有可见标签，placeholder 不能代替标签。
- 标签旁显示单位，或使用明确的单位选择器。
- 提供合理默认值，但不能隐藏默认值的工程含义。
- 协议与芯片使用预设时，允许用户查看和覆盖实际参数。
- 文本解析显示字节数、字符数或识别格式。
- 非法输入指出位置、原因和可接受格式。
- 不在用户输入过程中擅自改写可能有多种解释的数据。

## 5. 计算与结果

- 轻量、确定的计算随输入即时更新。
- 文件解析、设备授权和耗时操作使用明确按钮。
- 主结果使用最大视觉权重，详细结果按十六进制、十进制、二进制或字节序分组。
- 复制按钮只复制对应字段，并显示短暂成功反馈。
- 结果需要舍入时同时保存和说明内部精度。
- 计算失败时保留用户输入，方便修改。
- 结果附近展示验证状态或参考向量，不使用没有依据的“绝对正确”。

## 6. 示例与教学

- 每个工具至少提供一个经过测试的一键示例。
- 复杂协议工具可提供“常用示例”和“标准检查向量”。
- 原理摘要放在工具下方，完整推导链接知识文章。
- 代码示例明确语言、平台和适用范围。
- 常见错误优先解释工程中最容易产生错误结果的参数。

## 7. 搜索与导航

- 首页和工具箱都提供搜索，但共享同一搜索模型。
- 搜索结果清楚区分文章、工具、路线和速查。
- 工具少时不展示复杂筛选；数量增长后渐进增加。
- 当前页面在侧栏和面包屑中有清楚位置。
- 每个工具和文章均可通过独立 URL 分享。

## 8. 隐私与安全

- 默认在浏览器本地计算。
- 文件工具明确显示“本地处理、不上传”和大小限制。
- 涉及 Web Serial、Bluetooth、USB 或 HID 时，在请求权限前解释用途。
- 不保存用户输入，除非用户主动选择；保存范围和清除方式必须透明。
- 不在示例中要求用户粘贴密钥、生产固件或敏感日志。

## 9. 无障碍与响应式

- 所有主要操作能够仅用键盘完成。
- 表单有可关联的 label、错误描述和焦点状态。
- 颜色对比满足通用无障碍要求。
- 触控目标不应过小。
- 表格在窄屏允许横向查看或转换为键值布局。
- 代码和长十六进制字符串不撑破页面。
- 动画尊重系统的减少动态效果设置。

## 10. 组件化边界

第一批共享组件候选：

- `ToolHeader`：名称、描述、状态和隐私说明。
- `ToolField`：标签、单位、帮助和错误。
- `PresetSelector`：协议或芯片预设。
- `ExampleActions`：示例与重置。
- `ResultCard`：主结果、格式和复制。
- `ValidationBadge`：草稿、已测试、已验证。
- `RelatedContent`：文章、工具和速查链接。

只有在两个以上真实工具验证了相同结构后才提取共享组件，避免提前制造抽象。
