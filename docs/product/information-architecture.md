# 产品信息架构

## 1. 设计目标

EmbedAtlas 同时服务三种任务：

- **学习**：不知道从哪里开始，希望按照路线建立知识体系。
- **查阅**：已经知道主题，需要快速找到定义、参数或错误原因。
- **计算**：正在开发或调试，希望立即完成转换、计算或验证。

三个任务共用内容和搜索，但使用不同入口。

## 2. 全局导航

第一阶段顶层导航保持稳定：

```text
首页
├─ 学习路线
├─ 知识库
├─ 工具箱
├─ 速查
└─ 关于
```

“项目案例”“社区”“调试工作台”等远期模块只有在存在真实内容后才加入顶层导航。

## 3. 首页结构

建议顺序：

1. 品牌名称和一句话定位。
2. 全站搜索框。
3. “开始学习”和“打开工具箱”两个主操作。
4. 常用工具，第一版最多展示 6 个。
5. 初学者学习路线入口。
6. 核心知识分类。
7. 最近新增或最近验证的内容。
8. 开源贡献与项目说明。

首页不展示所有文章和全部工具，完整目录由知识库与工具箱页面承担。

## 4. 知识库

### 目录页

- 一级分类卡片。
- 每类展示代表主题和内容数量。
- 支持难度、标签和状态筛选。
- 没有正式内容的分类不在公开页面展示。

### 文章页

桌面端建议包含：

```text
左侧：知识分类与同级文章
中间：文章正文
右侧：本文目录、状态和关联工具
```

窄屏端收起左右导航，只保留正文和可展开目录。

## 5. 工具箱

### 目录页

- 搜索优先。
- 初期按“转换、校验、通信、MCU、硬件”分类。
- 工具达到一定数量后再增加技术标签和计数。
- 卡片显示名称、用途、关键标签、验证状态和本地处理说明。

### 工具页

每个工具拥有独立、稳定的 URL：

```text
/tools/base-bit-converter
/tools/hex-ascii-converter
/tools/crc-calculator
```

工具页结构：

1. 名称、用途、状态和隐私说明。
2. 输入、预设与示例。
3. 主结果和复制操作。
4. 详细结果与中间过程。
5. 原理摘要。
6. 关联知识、代码示例、常见错误和参考资料。

知识文章嵌入工具时可以使用精简组件，但独立工具页保留完整信息。

## 6. 学习路线

第一批路线：

- 嵌入式入门基础。
- MCU 与常用外设。
- 通信协议基础。
- FreeRTOS 基础。
- 嵌入式调试基础。

路线只保存顺序、前置关系和完成建议，不复制文章正文。

## 7. 速查

速查内容用于快速查询，例如：

- ASCII 表。
- C 数据类型和格式化符号。
- UART、SPI、I2C 模式与字段。
- 常用单位与数量级。
- 常见故障排查清单。

速查页面必须链接到深入文章，避免成为没有解释的孤立表格。

## 8. 搜索

搜索结果统一索引文章、工具、学习路线和速查资料，并明确显示类型。

优先字段：

- 标题和别名。
- 中文术语、英文术语与缩写。
- 分类与标签。
- 一句话描述。
- 支持的协议、芯片或数据格式。

例如搜索 `串口`、`UART`、`115200` 都应能够找到 UART 文章和相关计算工具。

## 9. URL 与增删原则

- URL 使用小写英文 `kebab-case` 标识，标题保持中文。
- 稳定发布后不随标题文字调整 URL。
- 删除内容时提供替代链接或废弃说明。
- 新模块通过元数据注册，导航尽量自动生成。
- 顶层导航变化属于产品架构变化，需要先更新本文件。
