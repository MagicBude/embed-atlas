# 项目愿景

## 1. 我们要解决的问题

中文嵌入式资料数量很多，但经常存在以下问题：

- 知识分散在视频、博客、论坛、芯片手册和个人笔记中。
- 内容常常绑定单一芯片或开发板，不容易迁移到其他平台。
- 文章讲原理、工具只给结果，两者没有形成学习闭环。
- 部分在线计算器没有公式、单位、测试依据或错误说明。
- 初学者不知道学习顺序，有经验的工程师又难以快速查阅。

EmbedAtlas 希望提供一个中文优先、结构清楚、能够验证并可持续维护的入口。

## 2. 目标用户

### 主要用户

- 正在学习 C、MCU 和常见外设的初学者。
- 从事 MCU、RTOS、IoT 或嵌入式 Linux 开发的工程师。
- 需要快速计算、转换、核对协议或排查问题的工程人员。
- 愿意整理经验、修正文档和贡献工具的社区成员。

### 暂非主要用户

- 只寻找特定厂商完整 SDK 替代品的用户。
- 需要云端团队管理或硬件实验室管理平台的企业用户。
- 需要功能完整的编译、烧录和调试 IDE 的用户。

这些方向可以在远期连接或探索，但不应破坏知识库和工具箱的核心体验。

## 3. 核心价值

### 中文优先，但术语准确

使用自然、清楚的中文解释概念，同时在首次出现时给出标准英文术语、缩写和必要的原文名称，方便读者继续查阅官方资料。

### 原理与工具相互连接

每个重要工具应链接对应的知识文章；知识文章遇到可计算、可转换或可验证的内容时，应链接相关工具。

### 结果透明并且可以验证

工具不能只显示一个数字。应说明输入含义、单位、采用的公式、舍入规则、边界条件和必要的中间结果。

### 从通用知识到具体平台

优先讲清通用原理，再补充 STM32、ESP32、RISC-V 或其他平台差异，避免整个知识体系被单一厂商目录绑死。

### 小步发布，长期积累

每个阶段都形成可以使用的结果。宁可先把三个工具和十篇文章做准确，也不追求首页展示几百个空分类。

## 4. 产品原则

1. 默认无需登录即可学习和使用基础工具。
2. 能在浏览器本地完成的计算，不上传用户数据。
3. 移动端可以查阅，桌面端适合工程输入。
4. 核心内容有来源，核心计算有测试。
5. 新增模块不能让已有模块难以独立维护。
6. 搜索和导航优先于装饰性动画。
7. 不以内容数量代替内容质量。

## 5. 长期方向

在知识库和工具箱稳定之后，可以逐步探索：

- 社区共建的学习路线和项目案例。
- 可离线使用的 PWA。
- 工具插件或可嵌入组件。
- 串口日志、协议帧和故障分析能力。
- 桌面调试工作台。
- 面向团队的高级功能或商业支持。

所有远期方向都需要先证明真实需求，并通过架构决策记录确认边界。
