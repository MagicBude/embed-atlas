# Phase 1 发布前检查清单

本清单用于判断 EmbedAtlas v0.1 是否可以公开访问。它区分“阻止发布的问题”和“可以在公开后继续完成的增强”，避免把项目拖入无期限完善，也避免在核心能力不可靠时仓促上线。

## 1. 发布信息

- 候选提交：`待发布时填写完整 Git SHA`
- 托管平台：`待确认`
- 公开 URL：`待确认`
- 检查负责人：`待确认`
- 检查日期：`待确认`

这些字段必须针对某个不可变提交填写。后续代码变化需要重新执行受影响的检查。

## 2. 必须通过：自动化质量

- [ ] 在全新环境使用 Node.js 22 执行 `npm ci` 成功。
- [ ] `npm run check` 成功，包括类型检查、核心测试、组件交互测试、内部链接检查和生产构建。
- [ ] GitHub Actions 对候选提交显示成功。
- [ ] `git diff --check` 无空白错误，工作树没有遗漏的发布变更。
- [ ] `site/.vitepress/dist/` 等生成物未进入 Git。

任何一项失败都阻止发布，不能用“本机可以运行”代替可复现检查。

## 3. 必须通过：内容与导航

- [ ] 知识库首页能够到达首批 10 篇文章，侧栏和上一页/下一页导航没有死链。
- [ ] 工具箱首页能够到达三个工具，每个工具能返回相关原理文章。
- [ ] 入门与通信基础学习路线只链接真实页面，不展示空分类入口。
- [ ] 文章 frontmatter、标题层级、代码块和参考资料格式符合内容规范。
- [ ] `review` 文章明确保持待同行审阅状态，没有显示“已验证”标记。
- [ ] README、`PROJECT_STATUS.md`、详细状态和工作日志反映候选提交的真实能力。

独立同行审阅不是 v0.1 公开预览的硬阻塞，但没有完成审阅的文章必须保持 `review`；只有满足内容系统门槛后才能逐篇升级为 `verified`。

## 4. 必须通过：工具行为

对进制与位运算、HEX/ASCII/UTF-8、CRC 三个工具分别检查：

- [ ] 默认示例能够产生预期结果。
- [ ] 至少一个典型输入、一个边界输入和一个非法输入表现正确。
- [ ] 错误信息指出具体问题，不静默截断、补零或替换非法数据。
- [ ] 重置、载入示例和复制反馈可用；复制内容与可见结果一致。
- [ ] 页面明确说明输入在本地处理，浏览器网络面板没有工具数据上传。
- [ ] CRC 的四个 `123456789` 检查向量与规格一致。

自动化测试通过后仍执行一轮真实浏览器冒烟检查，因为轻量 DOM 不能验证 CSS、剪贴板权限和浏览器差异。

## 5. 必须通过：浏览器与可访问性

- [ ] 当前主流桌面 Chromium 浏览器完成首页、知识库、工具箱和三个工具的冒烟检查。
- [ ] 390px 宽度下导航、表格、代码和工具没有整页横向溢出。
- [ ] 浅色与深色模式的正文、边框、错误和主操作具有可辨识对比度。
- [ ] 仅使用键盘可以到达导航、输入、选项和按钮，焦点样式可见。
- [ ] 表单具有可读标签，错误使用 `role="alert"` 或等效语义，动态反馈不会只依赖颜色。
- [ ] 404 页面和未知 URL 不出现空白页。

## 6. 必须通过：部署与安全边界

- [ ] 托管平台、仓库页面设置和最终 URL 已确认。
- [ ] 根据最终 URL 配置 VitePress `base`；根域和仓库子路径不能混用错误基础路径。
- [ ] 发布流程只具有所需最小 GitHub 权限，不使用长期个人令牌。
- [ ] 首次部署成功后，从公开 URL 重新检查资源、导航、搜索和三个工具。
- [ ] 已记录回滚方式：保留上一成功部署或能从上一提交重新发布。
- [ ] 不提交密钥、私有日志、设备数据、本地绝对路径或个人配置。
- [ ] 已知 Vite/VitePress 开发服务器公告不会暴露到公开生产服务；本地开发仍只监听 `127.0.0.1`。

## 7. 必须通过：许可证与项目入口

- [ ] 代码范围保留 MIT License，知识与项目文档范围保留 CC BY-SA 4.0。
- [ ] 第三方资料只做必要引用和原创解释，没有复制大段受版权保护内容。
- [ ] GitHub 仓库、编辑链接、贡献说明和许可证链接可访问。
- [ ] 首页没有尚未实现、容易让用户误认为可用的功能承诺。

## 8. 可以发布后继续完成

以下项目不是 v0.1 公开预览的硬阻塞：

- 十篇文章的独立同行审阅与逐篇 `verified` 升级。
- 自定义域名、访问统计、站点地图增强和搜索分析。
- 英文或其他语言入口。
- PWA、完整离线包、账号、云同步和桌面应用。
- 更多 MCU、RTOS、协议文章和 Phase 3 工具。
- 视觉品牌名称的长期定稿。

这些事项仍应进入路线图或状态文档，但不能让空入口提前出现在主导航中。

## 9. 发布后 24 小时检查

- [ ] 重新打开公开首页和三个工具，确认部署没有被后续提交破坏。
- [ ] 检查 GitHub Actions 与托管平台是否有失败或异常告警。
- [ ] 检查公开 Issue 中是否出现计算错误、死链、乱码或手机端阻塞问题。
- [ ] 若发现影响主要流程的问题，优先回滚或修复，并在 `CHANGELOG.md` 记录用户可感知变化。
