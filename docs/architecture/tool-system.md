# 在线工具系统

## 1. 目标

工具箱不是互不相关的页面集合。每个工具都应采用一致的输入、计算、错误处理、解释和测试方式，并且能够独立增加或删除。

## 2. 一个工具的组成

```text
工具需求规格
├─ 用户问题与适用范围
├─ 输入、输出和单位
├─ 公式、标准与参考向量
└─ 验收条件
        ↓
纯计算核心 ─────→ 单元测试
        ↓
Vue 交互组件
        ↓
工具说明页面 ←────→ 关联知识文章
```

任何工具都不能只有界面而没有独立的计算核心和测试。

## 3. 计划目录约定

以 `uart-frame-time` 为例：

```text
docs/tools/uart-frame-time.md             # 开发前需求规格，可选工作文档
site/tools/uart-frame-time.md              # 用户看到的工具页面
site/components/tools/UartFrameTime.vue    # 交互界面
site/lib/tools/uart-frame-time.ts          # 纯计算逻辑
tests/tools/uart-frame-time.test.ts        # 自动化测试
```

实际初始化站点时，如果目录有所调整，应先同步本文件。

## 4. 核心逻辑规则

- 函数不直接读写 DOM、浏览器存储或 Vue 状态。
- 输入和输出优先使用明确的数据结构，避免依赖参数顺序猜测含义。
- 带单位的值在变量名或类型中体现单位，例如 `clockHz`、`timeUs`。
- 对无效输入返回可识别的错误，不静默产生 `NaN` 或错误结果。
- 舍入、溢出、精度和字节序必须明确。
- 协议算法注明变体，例如不能只写“CRC-16”。
- 可以在浏览器本地完成的计算不得上传输入数据。

## 5. 界面规则

每个工具页面至少包含：

- 工具用途和适用范围。
- 带标签、单位和示例的输入区。
- 清楚的结果区以及复制或重置操作。
- 无效输入的具体提示。
- 公式、参数或必要中间结果。
- 常见误区与关联知识文章。
- 数据是否仅在本地处理的说明。

键盘操作、颜色对比和窄屏布局属于验收要求，而不是后期装饰。

## 6. 测试规则

工具测试分为两个互补层次：纯计算核心测试在 Node 环境运行，组件交互测试在轻量 DOM 环境挂载真实 Vue 组件。组件测试不重复证明算法，而是验证用户操作能把正确输入传给核心，并把结果和错误状态正确呈现出来。

每个工具至少覆盖：

1. 一个典型正常值。
2. 最小或零值等边界条件。
3. 最大合理输入或精度场景。
4. 非法字符、空输入或不完整参数。
5. 至少一个来自标准、厂商文档或可信实现的参考向量。
6. 曾经出现过的每个缺陷对应一个回归测试。

计算结果不能只用同一份实现反向验证自身。

组件交互至少覆盖与该工具相关的输入变化、模式或预设切换、错误提示以及重置或复制反馈。响应式排版和真实浏览器兼容性仍需浏览器验收，轻量 DOM 测试不能替代视觉检查。

## 7. 首批工具顺序

1. 进制与位运算转换器。
2. HEX、ASCII 与字符串转换器。
3. CRC 计算器。

这个顺序从简单状态和输入解析开始，再进入具有多个算法参数的 CRC，适合作为项目学习路径。
