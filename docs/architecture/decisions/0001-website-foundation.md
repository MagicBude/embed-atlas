# ADR-0001：使用 VitePress、Vue 和 TypeScript 构建第一阶段网站

- 状态：Accepted
- 日期：2026-08-23

## 背景

EmbedAtlas 同时需要大量以文字和代码为主的知识内容，以及能够在页面中直接使用的交互式工程工具。第一阶段还要求部署简单、无需后端、方便社区通过 Git 管理 Markdown 内容。

## 决定

第一阶段采用：

- VitePress 作为静态站点生成器和文档框架。
- Vue 作为交互式工具和定制界面的组件框架。
- TypeScript 编写工具核心逻辑和前端代码。
- Markdown 编写知识文章、工具说明和学习路线。
- 工具计算默认在浏览器本地完成。

## 理由

- Markdown 适合技术内容、代码示例和 Git 审阅。
- VitePress 可以直接在 Markdown 中使用 Vue 组件。
- 静态站点不需要维护服务器和数据库。
- TypeScript 有助于明确工具输入、输出和单位结构。
- Vue 组件能够逐步学习，不要求第一天搭建复杂应用状态。

## 影响

正面影响：

- 内容贡献者可以主要使用 Markdown。
- 工具与文章能够出现在同一个页面体系中。
- 部署和离线缓存的后续路径清楚。
- 第一版维护成本较低。

需要承担：

- 项目需要 Node.js 工具链。
- 复杂工具仍需设计好状态管理和测试边界。
- 如果未来发展为桌面应用，需要复用核心逻辑而不是直接复用全部页面结构。

## 未采用方案

- 从零开发完整 Vue SPA：自由度高，但需要自行建设大量文档能力。
- Docusaurus：同样可行，但会把首阶段学习重点转向 React/MDX。
- Python 文档框架：写文档简单，但在页面内开发 TypeScript 工具的整合路径不如当前方案直接。
- 一开始开发桌面应用：超出第一阶段“知识库 + 工具箱”的范围。

## 复审条件

出现以下情况时重新评估：

- VitePress 无法支持必要的搜索、内容组织或无障碍要求。
- 工具复杂度使静态页面架构无法合理维护。
- 项目确认需要账号、服务端数据或实时团队协作。
