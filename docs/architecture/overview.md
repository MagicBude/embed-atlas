# 总体架构

## 1. 架构目标

EmbedAtlas 的架构首先服务于长期维护，而不是追求复杂技术。它需要允许知识文章、工具、学习路线和未来模块独立演进，同时保持统一导航和使用体验。

核心约束：

- 内容与工具分离。
- 工具计算与界面分离。
- 项目治理文档与网站正文分离。
- 分类通过元数据组织，不依赖大量硬编码页面。
- 第一阶段保持静态和本地优先。

## 2. 系统分层

```text
用户界面层
├─ 首页、导航、搜索、主题与通用组件
├─ 知识文章页面
└─ 在线工具页面
        ↓
功能模块层
├─ 知识内容模块
├─ 工具交互组件
└─ 学习路线与关联推荐
        ↓
核心逻辑层
├─ 进制、CRC、协议与工程计算函数
├─ 输入解析、单位转换和结果格式化
└─ 分类、标签和内容元数据
        ↓
静态资源层
├─ Markdown、图片和示例数据
└─ 构建配置与测试参考向量
```

依赖只能由上向下。核心计算函数不得导入 Vue 组件、浏览器 DOM 或页面状态。

## 3. 计划目录

网站初始化后计划形成以下结构，具体细节可在实现时通过 ADR 调整：

```text
embed-atlas/
├─ AGENTS.md
├─ README.md
├─ CHANGELOG.md
├─ docs/                         # 项目规划、架构和规范
│  ├─ architecture/
│  ├─ development/
│  ├─ product/
│  ├─ project/
│  ├─ research/
│  ├─ standard/
│  └─ templates/
├─ site/                         # VitePress 站点根目录
│  ├─ .vitepress/                # 主题、导航和构建配置
│  ├─ knowledge/                 # 正式知识库文章
│  ├─ tools/                     # 工具说明与入口页面
│  ├─ learning-paths/            # 学习路线
│  ├─ reference/                 # 速查资料
│  ├─ components/tools/          # Vue 工具界面组件
│  ├─ lib/tools/                 # 与界面无关的计算逻辑
│  └─ public/                    # 静态资源
└─ tests/                        # 工具与内容相关自动化测试
```

## 4. 模块边界

### 知识模块

负责解释概念、原理、示例、错误和来源，不在 Markdown 中堆放复杂计算逻辑。详细设计见 `content-system.md`。

### 工具模块

每个工具由需求规格、纯计算核心、交互界面、测试和关联文章组成。详细设计见 `tool-system.md`。

### 学习路线

学习路线只引用现有文章和工具，不复制正文。路线可以按基础、岗位方向、技术主题和实践项目组织。

### 通用站点能力

导航、搜索、主题、SEO、无障碍和统计属于共享基础设施，不得由单个工具重复实现。

## 5. 扩展规则

新增方向时优先选择以下方式：

1. 新文章：加入已有知识分类。
2. 新工具：遵循统一工具模块接口。
3. 新分类：先确认至少有足够内容，避免空分类。
4. 新基础设施：通过 ADR 说明为什么现有结构无法满足。
5. 新产品形态：尽量复用纯计算核心和内容，不让网站依赖桌面端。

## 6. 暂不引入的能力

- 用户账号和权限系统。
- 云数据库与服务端渲染业务逻辑。
- 在线保存敏感固件、日志或项目文件。
- 复杂微服务和提前设计的插件运行时。
- 自建编译、烧录和调试 IDE。

这些限制不是永久禁止，而是保护第一阶段的可交付性。
